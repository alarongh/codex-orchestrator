# Структура проекта

Сначала прочитай корневые `README.md`, `AGENTS.md`, инструкции каталогов и существующий указатель документов. В пределах проекта применяй правило ближайшего к изменяемому файлу каталога. Codex загружает инструкции по пути до текущего рабочего каталога, поэтому проверь вложенные инструкции в местах, куда пойдёт исполнитель. В одном каталоге Codex предпочитает непустой `AGENTS.override.md`. [Порядок загрузки AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

Найди, где уже описаны запуск, архитектура, проверка и выпуск. Расширяй действующую схему. Для нового проекта начни с корневого README и добавляй разделы и файлы по фактическому объёму.

| Материал | Предпочтительное место |
| --- | --- |
| Вход в проект | `README.md`: назначение, быстрый запуск, проверка и ссылки на основные части |
| Правила работы агентов | `AGENTS.md` в нужной области проекта |
| Устойчивые сведения о продукте | Существующая документация или `docs/`: архитектура, эксплуатация, требования и релиз |
| Существенное решение | Существующий журнал или короткая связанная с задачей запись в `docs/decisions/` |
| Текущий статус длительной работы | Одна актуальная запись проекта или карточка задачи со ссылками на версии и результаты |
| Код, тесты и результаты | Соответствующие каталоги по правилам проекта. Крупные и временные выводы держи в предназначенном месте |

Давай файлам понятные имена по теме и назначению. Используй единообразие языка и оформления в пределах проекта. У документа должны быть ясный заголовок и введение в несколько строк. Располагай сведения в порядке, в котором их ищет читатель. Для длинного документа добавляй оглавление, если это упрощает навигацию. Делай один основной источник для каждого факта и ссылайся на него относительной ссылкой из README или ближайшего указателя. При перемещении файла обновляй ссылки. Проверяй, что по этим ссылкам можно найти вход, текущую версию, способ проверки и результат.

Для значимого решения используй компактную запись:

1. **Задача и основание.** Пользователь, сценарий, симптом или обязательное требование.
2. **Решение и причина.** Добавить, упростить, отложить или снять предложение. Укажи, что меняется и почему.
3. **Последствия.** Затронутые части, зависимости, издержки и обратимость.
4. **Проверка и статус.** Критерий готовности, ссылка на результат, оставшиеся вопросы.

В небольших задачах используй карточку, описание PR или короткий блок в существующем документе. Поддерживай актуальность этих записей при смене решения или статуса. Логи, частные промежуточные данные и переписки сохраняй только там, где они действительно нужны для работы и их разрешено хранить. Для документов используй [маршрут к document-manifest](deliverables.md).
