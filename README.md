# Codex Orchestrator

Один вход для задач Codex. Ведущий выбирает прямую работу, одного исполнителя или разделение работы с приёмкой. Он подключает навыки по формату, инструменту или конкретной проверке и сверяет итог по исходникам. Веб-интерфейс открывается во встроенном браузере Codex, когда он доступен.

## Установка

1. Скопируйте каталог [`.agents/skills/codex-orchestrator`](.agents/skills/codex-orchestrator) целиком в `~/.agents/skills/` для всех проектов или в `.agents/skills/` нужного проекта. На Windows `~` – домашняя папка пользователя. Если вы открыли этот репозиторий как проект в Codex, скилл уже находится в нужном месте.
2. В новом чате задайте работу, например: «`$codex-orchestrator` Подготовь отчёт по приложенному шаблону и журналу испытаний. Проверь каждое требование и собери архив для сдачи».
3. Для постоянного режима добавьте нужные строки из [примера AGENTS.md](examples/AGENTS.md) в существующий пользовательский или проектный `AGENTS.md`. Не заменяйте существующие инструкции. Это опционально: скилл доступен по имени и может выбираться автоматически без этого шага.

## Модели и параллельность

| Роль | Модель | Усилие |
| --- | --- | --- |
| Поиск и извлечение фактов | Новейшая доступная Luna | `low` |
| Визуальная сверка при необходимости | Новейшая доступная Terra | `low` |
| Исполнитель | GPT-6.2 Sol | `low` |
| Критик отчёта | GPT-6.2 Sol | `medium` |

Скопируйте файлы ролей в `~/.codex/agents/` для личного использования или в `.codex/agents/` проекта. Модель и усилие ведущего выбирает пользователь в Codex. Скилл и профиль их не задают. В CLI скопируйте файл примера в каталог конфигурации Codex под именем `orchestrator.config.toml` и запустите `codex --profile orchestrator`. В профиле по умолчанию подагент получает Sol 6.2 с `low`. Лимит в три открытых подагента оставляет место для независимых задач. [Файлы ролей](.codex/agents) · [Профиль CLI](examples/orchestrator.config.toml) · [Настройки подагентов](https://learn.chatgpt.com/docs/agent-configuration/subagents)

При наличии более свежей Luna или Terra ведущий выбирает её при запуске, учитывая фиксированные настройки роли. При недоступности Sol 6.2 он не переключается на старый Sol: лёгкую часть можно передать подходящей актуальной Luna или Terra. Если подходящего агента для обязательного этапа нет, ведущий сообщает о пробеле.

## Что делает ведущий

| Сценарий | Рабочий порядок |
| --- | --- |
| Учебная работа или отчёт | Сверка задания и источников → исполнитель → строгий критик → правки и повторная сверка |
| Документ | Подключение `document-manifest` до работы; навык формата только при отдельной необходимости |
| Новая функция | Оценка необходимости и последствий → решение ведущего → исполнитель → интеграция и тесты |
| Веб-сервис | Оценка применимости и проверка 20 пунктов при первом аудите. При точечной правке проверяются затронутые сценарии |
| Идея продукта | Минимальный проверяемый результат, при необходимости отдельные предложения по развитию |
| Аудит или релиз | Проверка цели, версии, доступа и доказательств → аудит или разрешённая публикация |
| Короткий вопрос или локальная правка | Прямая работа и точечная проверка, без запуска агентов |

Ведущий может добавлять обратимые улучшения в пределах цели. Внешние действия требуют уже выданного разрешения. Исполнители предлагают идеи отдельно и не меняют объём работ самостоятельно. Общение нейтральное. Запрет на тире касается U+2014; дефисы, короткое тире и математический минус остаются.

В главном файле скилла описана иерархия правил и ролей. Из него подключаются нужные модули. Материалы проекта связываются с README или ближайшим указателем, а существенные решения получают запись с основанием, последствиями и результатом проверки. [Вход в скилл](.agents/skills/codex-orchestrator/SKILL.md) · [Структура проекта](.agents/skills/codex-orchestrator/references/project-structure.md) · [Проверка веб-сервиса](.agents/skills/codex-orchestrator/references/web-review.md). В простом запросе скилл может вообще не понадобиться. Скилл сам не меняет настройки, не устанавливает сторонние хуки, не повышает разрешения и не гарантирует доступность инструментов клиента. Если делегирование запрещено или недоступно, он выполняет доступные этапы и указывает, что осталось неподтверждённым.
